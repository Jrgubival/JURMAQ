- Broken `<a href="/api/barraca/...">` PDF download links: **2** (same root cause as fetch URLs)

### Root cause (urgent)

- Almost every `BROKEN_NO_ROUTE` entry is the same bug: **the Barraca frontend prefixes its fetch URLs with `/api/barraca/...`, but the actual Next.js App Router handlers live at `/api/...` (no `barraca` segment).** There is **no rewrite** in `apps/barraca/next.config.ts` or `apps/barraca/src/middleware.ts` that maps `/api/barraca/*` → `/api/*`, so every one of these requests returns 404 at runtime.
- The Constructora app does **not** use a `/api/constructora/` prefix; its fetches go straight to `/api/...` and all resolve correctly.
- Recommended fix: either (a) strip the `/barraca` segment from every fetch URL in `apps/barraca` (mechanical, low-risk), or (b) move every route file from `apps/barraca/src/app/api/<x>` to `apps/barraca/src/app/api/barraca/<x>`. Option (a) is preferred.

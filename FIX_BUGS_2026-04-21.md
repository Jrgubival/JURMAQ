# Bugs arreglados — 21 abril 2026 (madrugada)

## Los 4 bugs criticos que reportaste

### 1. Admin daba 404 despues de iniciar sesion
**Causa:** La pagina de login esta en `barraca.jurmaq.cl` pero el panel admin en `jurmaq.cl`. El codigo hacia `router.push("/admin")` que se quedaba en el subdominio → `barraca.jurmaq.cl/admin` → 404.
**Fix:** Ahora hace `window.location.href = "https://jurmaq.cl/admin"` que cruza de dominio correctamente.
**Archivo:** `src/app/barraca/cuenta/login/page.tsx`

### 2. Cliente iniciaba sesion y no persistia
**Causa raiz:** Cookie de NextAuth configurada solo para `jurmaq.cl` (sin `domain=.jurmaq.cl`), asi que cuando iniciabas sesion en `barraca.jurmaq.cl` la cookie no viajaba de vuelta a `jurmaq.cl`. El cliente aparecia como no logueado. Ademas el admin recibia token `admin_<id>` que el endpoint `profile` rechazaba.
**Fixes:**
- Cookie `Domain=.jurmaq.cl` en production → se comparte entre subdominios
- Admin ahora recibe token formato base64 seguro (igual que clientes)
- `Sec-Fetch-Site: same-origin` como fallback en CSRF (evita falsos 403)
**Archivos:** `src/lib/auth.config.ts`, `src/app/api/barraca/auth/route.ts`, `src/lib/sanitize.ts`

**Verificacion live:**
```
set-cookie: __Secure-next-auth.callback-url=...; Domain=.jurmaq.cl; Path=/; HttpOnly; Secure; SameSite=Lax
```
La cookie ya se setea con el dominio padre → funciona cross-subdominio.

### 3. Solicitudes mostraban "Invalid Date" y cliente vacio
**Causa:** La pagina usaba nombres viejos (`cliente`, `fecha`, `maquinaria`) pero la DB tiene (`cliente_nombre`, `created_at`, `maquinaria_nombre`). Todos undefined → Invalid Date y celdas vacias.
**Fix:** Interface y renderizado alineados con el schema real. Agregue guard contra fechas invalidas (`isNaN(d.getTime())`).
**Archivo:** `src/app/admin/solicitudes/page.tsx`

### 4. Cotizaciones admin (seccion general) — misma clase de bug
**Causa:** La pagina `admin/cotizaciones` enviaba `cliente`, `monto`, `fecha`, `validez_dias`, `descripcion` al POST pero la DB espera `cliente_nombre`, `monto_total`. Crear cotizacion fallaba silenciosamente.
**Fix:**
- Formulario ahora usa nombres DB correctos + campos `cliente_empresa` y `cliente_telefono`
- POST endpoint acepta AMBOS formatos (camelCase y snake_case) por compatibilidad
- Uso `created_at` para fecha en la tabla
**Archivos:** `src/app/admin/cotizaciones/page.tsx`, `src/app/api/cotizaciones/route.ts`

## IMPORTANTE: que debes hacer cuando despiertes

Con el cambio de cookie de `next-auth.session-token` a `__Secure-next-auth.session-token` (mismo token, nombre distinto por el prefijo que requiere domain-sharing), **tu sesion actual quedara invalida**. Tienes que:

1. Cerrar sesion (o simplemente cerrar pestanas)
2. Borrar cookies del navegador para `jurmaq.cl` y `barraca.jurmaq.cl` (Cmd+Shift+Delete → cookies)
3. Entrar de nuevo a login con tus credenciales
4. Deberia redirigirte automaticamente a `jurmaq.cl/admin` sin 404
